A network fixer that has to ask permission first

Simulated. An automated tool spots a misconfigured computer, proposes the fix and waits. Nothing changes until a person approves it, and every step is logged.

  • What it proves: an unapproved fix is refused; an approved fix clears the problem; a decided fix can’t be approved again; the app can’t edit or delete the history log; the 3D map turns the faulty computer from red to green after an approved fix.
  • What it doesn’t prove yet: simulated network only; no AI inside, it follows fixed rules; the approver is a fixed name, not a real login; someone with access to the computer could still delete the whole log file.
  • Bundle: governed-agent.zip: code, self-test output, an HTTP gate test you can re-run yourself, and before-and-after captures of the 3D map.

How to check a bundle

  1. Download the bundle and SHA256SUMS, then run sha256sum -c SHA256SUMS --ignore-missing. Each bundle you downloaded should say OK.
  2. Unzip it and run sha256sum -c FILES.sha256 inside the folder. Every file should say OK.
  3. Open README.md in the bundle. It lists which file backs each claim.

Then check the signature. SHA256SUMS is signed with my release key. Take the key from GitHub, not only from this site: it is listed at https://api.github.com/users/x8hunta/ssh_signing_keys. Download SHA256SUMS.sig, put the key in a file, then verify:

echo "_x8hunta <key from GitHub>" > allowed_signers
ssh-keygen -Y verify -f allowed_signers -I _x8hunta -n file -s SHA256SUMS.sig < SHA256SUMS

It should report a good signature for _x8hunta. The same key is in allowed_signers on this site. If the two keys differ, trust neither.
