The Power Grid Dependency: When One System Silently Blinds Another

Assume the digital layer will eventually lie, and make sure something physical can catch it.

What happened

This is a simulated scenario I designed for practice.

At a power utility, three assets depend on each other:

  • A transformer carrying the load.
  • A control system (SCADA) that reads the transformer’s data.
  • A load-balancing ledger that uses the control system’s data to report how loaded the grid is.

A firmware update on the control system added a delay. Because of the delay, the ledger reported that everything was fine. In reality, the transformer was running at 98% of its capacity.

The technician’s view

The firmware update is buggy. Roll it back or patch the delay.

That fixes this update. It doesn’t stop the next change to the control system from blinding the ledger in the same way.

The architect’s view

This was a dependency failure. Each system trusted the one before it, so a fault in the middle quietly corrupted everything downstream. Nobody had mapped which assets depended on which, and nothing checked the reports independently.

I map assets by their role:

  • Source of truth: the transformer. It’s what physically happens.
  • Processor: the control system. It reads and transforms the data.
  • Consumer: the ledger. It relies on the processor’s output.

Any change to a processor should put every consumer on alert.

The control: Conservative Override with Independent Sensors

  1. Physical sensors: independent heat sensors on the transformer detect overload no matter what the software reports. They don’t run through the control system, so one software bug can’t blind both.
  2. Assume the worst: when signals disagree, the system acts on the most dangerous one. If the heat is high but the reported load is low, it treats the load as high.
  3. Automatic safe state: a disagreement triggers load shedding and switches the system to manual oversight.

How to prove it works

After every update to a processor, confirm that its consumers were automatically flagged for revalidation. In testing, feed in a high temperature against a low reported load, and confirm the system sheds load and alerts an operator.

Takeaway

A false alarm is cheap. A missed overload isn’t. Design the system to prefer the false alarm.
