Attack and Defense Sandbox: I broke into my own trading app, then made sure I'd get caught

A fake trading app with fake money, attacked by my own scripts. First nothing caught the attacks. After the fixes, every attack set off an alert in under a second.

The story

I built a small trading app with made-up accounts and ran three attacks against it, the way real intruders get in with “valid” logins:

  • guessing passwords until one works,
  • using an API key that should have expired,
  • having an admin quietly switch a dead account back on.

Before: the app wrote everything to its log, but nobody was alerted. The expired key and the revived account went completely unnoticed. A log nobody reads protects no one.

After: I added controls and ran the same attacks again. Password guessing was blocked and alerted. The expired key was rejected and alerted. Reviving the dead account set off an alert. Each one fired in under a second.

The first attempt failed, and that’s in here too. In an earlier exercise I stole and replayed a login cookie. My network sensor saw nothing, because it couldn’t see traffic between the containers. A security camera pointed at the wrong room.

What it proves

Those three attacks are now detected in this lab, measured before and after. The 13 unit tests for the controls pass on the released code.

What it doesn’t prove yet

  • An alert isn’t a block. The dead account still comes back; now someone hears about it. (The network fixer is my answer to that: make it ask first.)
  • The code has an extra check that requires MFA before a dead account can be revived, and its unit test passes. But the lab app ran with that check switched off.
  • Lab only, with fake data, and my own scripts as the attacker.
  • The cookie-theft exercise found its gaps but hasn’t been re-tested after fixes.
  • One check (a login from a new IP address) was tested in code, not re-run as an attack.

For network people

MITRE ATT&CK T1078 (Valid Accounts) and T1539 (Steal Web Session Cookie). Docker lab, Flask mock API, Python middleware, Zeek. Built with AI help; the finished playbooks are saved as reusable skills for my AI assistant.
