A network fixer that has to ask permission first

An automated tool spots a misconfigured computer, proposes the fix, and waits. Nothing changes until a person approves it, and every step is written down.

The story

Automation is fast, and fast mistakes spread. So this tool is only allowed to do three things on its own: notice, suggest and wait.

It keeps an official record of how every computer on the network should be set up, and compares it with how each one is actually running. When a computer drifts, say it has lost its network address, the tool flags it and proposes the fix from the record. Then it stops.

Try to apply the fix before anyone approves it, and the tool refuses. Once a person approves, it applies the fix, checks the network against the record again, and the problem turns from red to green on a 3D map. Every step, including every refusal, goes into a history log the app can’t edit or delete.

What it proves

The approval gate works:

  • An unapproved fix is refused (the server answers “409 Conflict”).
  • An approved fix clears the problem.
  • A fix that’s already been decided can’t be approved or rejected again.
  • The history log refuses edits and deletes, and survives a reset of the demo.

What it doesn’t prove yet

  • It runs on a simulated network, not real equipment.
  • The “fixer” follows fixed rules. There is no AI in it yet.
  • The approver is a fixed name, not a real login.
  • When a fix is waiting, nobody is notified. Someone has to look.
  • Someone with access to the computer could still delete the whole log file. There’s no copy kept anywhere else yet.

For network people

The register holds intended L3 config for two /29 subnets and is the source of truth. A detector reconciles live state against it and logs findings; the agent turns findings into proposals; an apply gate refuses anything not approved. The audit table is append-only, enforced by database triggers. FastAPI, SQLite, vanilla JS, 3d-force-graph. Test case: a host with no IP, mask or gateway, taken from a routed troubleshooting lab.
